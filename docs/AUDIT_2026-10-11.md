# Audit: security, integrity, reliability, product readiness (2026-10-11)

## Verified OK (code + live Supabase catalogue)
- RLS enabled on all 6 public tables; every policy is `auth.uid() = user_id` (learner data) or `published = true` (catalogues), `to authenticated`.
- No INSERT/UPDATE/DELETE grants for `anon`/`authenticated`; `answer_key` columns are not granted to client roles.
- All 3 RPCs are `SECURITY DEFINER` with `search_path = ''`, not executable by `anon`, and derive the user from `auth.uid()`.
- API verifies the bearer token via Supabase Auth and uses a request-scoped client; learner ID never comes from the body.
- XP: lesson XP only on first pass (row lock + `lessons_completed`); milestones unique per `(user_id, event_key)`; attempt IDs idempotent; per-learner row lock serialises concurrent retries.

## Sixth follow-up: CSP enforcing (owner decision)
- Switched `Content-Security-Policy-Report-Only` to enforcing. Production `VITE_TRADEQUEST_API_URL` is `https://tradequest-api-ooalade-wlvacuks-projects.vercel.app` (not same-origin), so that origin and `tradequest-api.vercel.app` were added to `connect-src` alongside `https://*.supabase.co`; `'self'` alone would have blocked every API call.
- Anything new the app talks to (analytics, another API host, websockets) must be added to `connect-src`.
- Housekeeping: the `tradequest` frontend Vercel project also carries `SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_SECRET_KEY` (integration-injected, not `VITE_`-prefixed so not bundled). Recommend removing them from the frontend project.
- **Enforced-CSP browser check (headless Chrome, built app served locally with the exact `vercel.json` header):** app renders with no script/style violations; Supabase origin allowed (request reached server, 401); API origin allowed by CSP (call failed only on CORS because localhost is not the API's allowed origin); `https://example.com` blocked with an explicit CSP violation. Live site header confirmed enforcing. The live site itself could not be driven from the audit machine (Vercel bot challenge on that IP). Signed-in console check still needs a human.
